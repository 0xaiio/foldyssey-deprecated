> 目的：让评审看到"这是怎么做出来的"，包括需求、决策、执行步骤、提交与测试。
> 所有 SHA 来自 `git rev-parse HEAD`，可对照 https://github.com/0xaiio/foldyssey/commits/main

## 一、起点：一份需求文档

项目始于 `ai/Foldyssey-Prompt.md`：一份包含品牌、几何定义、关卡设计、发布与工程治理要求的长文档。
第一步不是写代码，而是**盘出歧义**并记录假设（`docs/ASSUMPTIONS.md`，10 条）：

- "一刀"到底是切一条线还是移除一个半平面 → 选择后者（否则不会产生孔洞）
- 折叠预设的物理可复现性边界 → 只承诺四种固定折法
- 运行时 AI 是否必须 → 无法确认安全通道时**不提供入口**
- 作品持久化 → localStorage，不引入云数据库
- 许可证 → 不擅自选择

## 三、关键实现思路（以及踩过的坑）

### 1. 展开不是"再折一次"

最初把展开写成 `transform(source)`，结果四层被折叠了两遍，展开面积只剩 1/4。
正确关系是：`source` 本身就是纸面坐标，展开 = 各层 `source` 的并集。
这个错误现在被 `geometry.test.ts` 的「两次正交折叠后展开恢复整张纸」锁死，
也写进了 `docs/GEOMETRY_SPEC.md` §5。

### 2. 一刀 = 半平面，不是线段

把线段的面积减掉不会产生孔洞。实现为：对每一层求 `D_i = f_i(P_i) ∩ H⁻`，
再 `P_i' = P_i \ f_i⁻¹(D_i)`。黄金关卡的 `2d²` 就是这么来的。

### 3. 折叠动画 = 反射矩阵的插值

`diag(1-2p, 1)` 在 `p=0.5` 时缩放为 0，正好是"纸边翻起正对观察者"的正交投影。
所以动画不是关键帧拼出来的，而是**同一个矩阵公式**在时间上的采样。

### 4. 一个只有截图能抓到的 bug

第 3 关通关后，判定显示"完全吻合"，但纸仍然画成折叠的纸包。
原因：状态机的 `revealed` 分支落到了默认的 `setAnim(1)`。
第 1 关没有折叠，所以看不出来；第 3 关一测就暴露。
修复后补了注释，并在 `docs/TEST_REPORT.md` 里记录了这个案例。

### 5. 检查器比代码更容易骗人

`innerText` 返回的是**渲染后**的文本，而 `IoU` 标签有 CSS `uppercase`，
所以正则 `/IoU/` 永远匹配不到，一直读到 `null`。改成大小写不敏感后才拿到真实数值。
这类"探针自身出错"的情况在 `TEST_REPORT.md` 中单独记录，避免误判产品有问题。

## 四、工具使用

| 阶段 | 工具 | 用途 |
|---|---|---|
| 需求 | 文档阅读 + 假设记录 | 把长文档拆成 40 条带 ID 的需求 |
| 几何 | Node + Vitest | 每次改动都跑数学断言，先在终端里验证再进 UI |
| UI | Vite dev server + Edge headless (CDP) | 截图、点击、拖动、读取 DOM 文本 |
| 验证 | `tools/ui_check.py`、`tools/level_check.py` | 自动生成截图与 JSON 报告 |
| 版本控制 | git + GitHub | 每个里程碑一次具名提交，推送后核验远端 SHA |
| 文档 | Markdown | 与代码同批提交，避免脱节 |

## 五、如何导出/分享 WorkBuddy 创作对话

平台若要求提交创作记录：

1. 在 WorkBuddy 打开本任务的对话；
2. 使用会话菜单中的**导出/分享**能力（不同版本入口名称可能不同，通常在会话右上角）；
3. 若没有导出功能，可截取关键对话段落，或直接提交 `TASKS.md` + `TEST_REPORT.md` + 本文件，
   它们记录了同样的决策链与验证过程。

> 不要提交包含个人信息、手机号或密钥的对话截图。

## 六、可复现性

```bash
git clone https://github.com/0xaiio/foldyssey.git
cd foldyssey
npm ci
npm test          # 57 条断言
npm run build
npx vite preview --port 4173
```

同一个 `d`、同一组切线参数，在任何机器上都得到同一个孔洞——这是本项目的核心承诺。

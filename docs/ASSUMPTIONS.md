# 假设与歧义澄清（ASSUMPTIONS）

> 规则：遇到名称、几何语义、部署 API、AI 权限、验收阈值等不明确内容，先记录「问题 → 理解 → 假设 → 依据 → 风险 → 可撤销措施」，然后按可逆默认值执行。
>
> 只有影响重大且没有安全默认值的阻塞问题才停下来询问用户。

## A-001 运行时 AI 是否必须接入

- **问题**：赛事是否强制要求作品内调用大模型？WorkBuddy 能否提供安全的无密钥运行时通道？
- **理解**：需求文档将 AI 设计助手列为 P1/C 级增强，并明确要求"若平台无法提供合适的运行时 AI 能力：隐藏不可用入口，保留全部数学游戏与工坊功能；不要用固定内容伪装真实大模型调用"。
- **假设**：在无法确认一条**不需要用户自备密钥**、可限流、可降级的运行时模型通道之前，**不实现、不露出** AI 入口。文档与投稿材料中如实标注「运行时 AI：未实现」。
- **依据**：需求文档 §8.1、§13 Gate A（AI 不在 Gate A 内）、§17（禁止伪完成）。
- **风险**：若官方规则强制要求运行时 AI，则该项会成为 Gate A 缺口。
- **可撤销措施**：几何引擎与参数化图案已按"可由结构化参数驱动"设计（`StraightCut[]` + `FoldPresetId`），接入模型时只需在外层加一层自然语言 → 参数 → Schema 校验的适配器，不改动几何内核。

## A-002 "一刀"的几何语义

- **问题**：文档提到"一条直线"，但也提到"半平面""移除侧"。一条零宽度的线不产生面积，无法形成孔洞。
- **理解**：一次剪切 = 折叠纸包中的**一条完整直线** + 一个明确的**移除半平面**（`n·p < c` 或 `n·p > c`）。切下的部分与保留的部分由这条线划分。
- **假设**：`StraightCut = { nx, ny, offset, removedSide }`，`n` 为单位法向量，`offset` 为直线到原点的有符号距离。
- **依据**：§5.3 明确要求"必须处理被剪掉的一侧、连通区域和孔洞"，并禁止"将无面积的数学线段本身从纸张面积中相减"。
- **风险**：用户可能把"画一条线"理解为"沿线切开但不移除任何一侧"（像划线一样）。本作明确以"剪去某一侧"为语义，并在 UI 中用阴影区 + "剪去正侧/负侧"标签表达。
- **可撤销措施**：若未来要支持"只切开不移除"（例如分离但不掉料），需要引入裂缝（slit）模型，与现模型并存，不影响现有 API。

## A-003 折叠预设的物理可复现性

- **问题**：程序可以计算任意折叠的几何，但"能算"不等于"能用手折出来"。
- **理解**：P0 只实现四种固定折法（不折 / 竖直中线 / 水平中线 / 正交双折），每一步的折叠方向固定（左→右、下→上），折痕始终经过纸心且不移动。
- **假设**：把这四种折法视为**已验证可执行**的折叠序列；工坊导出的"手工制作卡"只描述这四种折法下的折叠与剪切，不承诺其他折法。
- **依据**：§5.2 要求"P0 必须明确限制为经过验证的固定折叠预设"。
- **风险**：真实纸张有厚度，多次对折后切口会出现微小的层间偏移；本作不建模厚度。
- **可撤销措施**：手工制作卡中显式声明"纸张厚度与折叠精度会影响实际效果"。

## A-004 作品中"已验证"标签的含义

- **问题**：`manufacturability: 'verified'` 到底验证了什么？
- **理解**：验证的是**几何层的可执行性**：存在一个确定的折叠序列和若干条直线切口，其逐层几何结果等于所展示的图案。
- **假设**：只要作品由 `FoldPresetId` + `StraightCut[]` 构成，且展开结果由引擎算出，就标记为 `verified`；不声称通过物理打样。
- **依据**：§7.4 要求模板包含纸张尺寸、折叠顺序、每步纸包轮廓、切线与保留侧。
- **风险**：用户可能把 `verified` 误读为"已实物验证"。
- **可撤销措施**：UI 文案固定为"折剪方案已验证（几何层）"，并提供几何读数；如未来做实物打样，可增加 `physically-tested` 级别。

## A-005 关卡数量的降级顺序

- **问题**：文档要求 6 关，同时允许"至少 3 关 + 工坊 + 公开链接"。
- **理解**：先保证 3 关可玩 + 工坊 + 发布（Gate A），再补到 6 关（Gate B）。
- **假设**：本次实现 6 关，但每关都必须由**标准解正向构造**并通过自动校验；若某关无法验证，则删除该关而不是保留假关卡。
- **依据**：§6.1、§13。
- **风险**：关卡数量与质量冲突时，以质量为先。
- **可撤销措施**：`src/puzzle/levels.ts` 中每关都有 `canonicalCut`，`src/tests/levels.test.ts` 逐关断言"标准解 → 完全吻合"。

## A-006 作品持久化

- **问题**：是否需要云数据库？
- **理解**：不需要。文档明确"初版完全本地保存，无需服务器"，并建议 localStorage 或 IndexedDB。
- **假设**：使用 localStorage，键 `foldyssey.gallery.v1`（作品）与 `foldyssey.progress.v1`（进度），带 `schemaVersion` 与容错读取。
- **依据**：§4.4、§11。
- **风险**：localStorage 有容量上限（约 5MB），且清理浏览器数据会丢失作品。
- **可撤销措施**：只保存结构化参数 + 一份路径缓存，不保存位图；UI 提示"请先用 SVG 导出留档"。

## A-007 赛事规则核验状态

- **问题**：活动页面的投稿字段、评分权重、AI 强制要求需要登录才能看到。
- **理解**：无法自动读取的字段一律标记「待人工核验」，不编造。
- **假设**：以公开报道中的"网页应用/小程序、需作品介绍与可体验链接"作为准备依据；具体表单字段由用户登录后确认。
- **依据**：§1.1、§17。
- **风险**：若官方要求特定材料（如演示视频时长、截图尺寸），需在投稿前补齐。
- **可撤销措施**：`submission/contest_form_checklist.md` 列出待确认项，不预填任何未经核实的字段。

## A-008 许可证

- **问题**：仓库没有 LICENSE，是否要替用户选一个？
- **理解**：文档明确"不得未经用户授权擅自选择项目开源许可证"。
- **假设**：暂不添加 LICENSE，README 与 About 中标注"版权归作者所有，保留一切权利"，第三方依赖许可单独列出。
- **依据**：§15.4。
- **风险**：他人无法合法复用代码。
- **可撤销措施**：`LICENSE_DECISION.md` 记录候选方案（MIT / Apache-2.0 / 双许可），由所有者最终决定。

## A-009 坐标与渲染方向

- **问题**：数学坐标 y 向上，SVG 坐标 y 向下，容易在交互与导出中出错。
- **理解**：模型空间统一 y 向上；渲染时用一个 `scale(1,-1)` 的组翻转；指针输入通过 `getScreenCTM()` 逆变换后取负 y。
- **假设**：所有几何函数只接受模型坐标；任何屏幕坐标转换都集中在 `PaperStage` 与导出模块。
- **依据**：§9.4 要求"手机画布按真实 viewBox 坐标映射触控点"。
- **风险**：新增渲染组件若忘记翻转，会出现上下镜像。
- **可撤销措施**：`src/tests/geometry.test.ts` 与 UI 检查脚本覆盖方向一致性。

## A-010 缩放与容差

- **问题**：多边形布尔运算在退化输入（重合边、共线、极小面积）下可能抛错或产生碎片。
- **理解**：统一使用 `EPS = 1e-9`（面积/点比较）与 `SNAP = 1e-7`（顶点合并）；布尔运算前清洗环、丢弃退化多边形，失败时降级并计数。
- **假设**：评分容差 `IoU ≥ 0.995` 记为"完全吻合"，`≥ 0.9` 记为"接近"；关卡可单独覆写。
- **依据**：§5.5、§12.1。
- **风险**：容差过严会让触控微差被判失败；过松会放过错误解。
- **可撤销措施**：容差写在关卡数据里（`tolerance`），可逐关调整而不改引擎。

## 2.2 产品使命

**让用户用极少的动作，亲自发现复杂的纸艺之美如何从几何规则中产生。**

不同于静态折纸教程、传统画板和图片生成器，用户需要真实操作纸张：折、剪、看、改，再把数字作品带到现实世界。

核心循环：**Guess → Fold → Snip → Unfold → Discover → Create → Share**。

每次试玩体验应具有：

- **10 秒内**理解怎么玩；
- **约 30 秒内**完成一个无需输入的默认例子；
- 展开一刻出现惊喜；
- 允许失败与重试，而不是只播放固定动画；
- 能说明“我动了哪里，为什么结果改变”；
- 能生成值得分享、可复现或可保存的原创作品。

以上是产品体验目标，实际完成后需通过操作观察验证，不得未经计时声称达标。

## 2.3 文化与研究融合

结合中国传统剪纸（窗花、喜庆纹样、节日礼物）、折纸中的对称和层叠、现代生成艺术与计算几何。整体风格要呈现**“数学实验室 × 纸艺博物馆 × 创造性小游戏”**。

研究灵感来自 Erik Demaine、Martin Demaine 等人的 **Fold-and-Cut Problem**：纸张经过适当的**一般平折**后，一个完整的直线切割可实现任意由直线段组成的切割图案。但本产品第一版仅支持很有限的合法折叠族，**不能宣称任意目标图案均可由两次简单对折后一刀剪出**。

必须在 About 页明示：受计算折纸研究启发，**非 MIT 官方产品、非 Demaine 合作/背书项目**；不直接搬用其谜题图片、教材图、源码或其它受限资源。

# 3. 模式划分：严谨的一刀、自由的剪纸、可选的 AI

本项目有三个**互相协作但物理意义不同**的功能模块。

## A. 一刀挑战（One-Cut Puzzle）——核心 P0

- 玩家选择合法折叠方案；
- 在**最终平折的纸包**上放置/拖动**一条直线**；
- 用一次连续的直线切割得到实际几何结果；
- 逐层展开，对照目标并计算分数；
- 可重试、查看提示、验证与回放。

**一刀的定义**：一次剪切只能沿折叠纸包中的单一完整直线进行。不能把绘制任意闭合轮廓、随机多边形擦除、多个切口合称“一刀”。如果允许剪切线贯穿纸包外的空白部分，算法只需作用于它与每层纸包的交集；需保证切下部分与真实剪切语义一致。

## B. 剪纸工坊（Paper Art Studio）——核心 P0 / 增强 P1

- 左侧折叠工作台 / 右侧实时展开预览；
- 可编辑切线与已支持的多切口或参数化孔洞；
- 中国红窗花、雪花、现代几何花纹等审美预设；
- SVG/PNG 导出、本地保存、重新加载；
- 可选实体模板。

重要：**数字旋转/镜像对称图案 ≠ 已证明的实体折剪方案**。需要清晰区分 `Digital Pattern` 与 `Verified Fold-and-Cut Template`。艺术工坊可包含多切口甚至曲线装饰，但**不得**用它们冒充一刀挑战关卡。

## C. AI 灵感设计师（AI Design Companion）——P1 增强

- 自然语言提出艺术主题；
- 模型只负责生成**受控结构化的设计参数**、创意文案与解释；
- 经过 Schema 校验、合法性检查后由**确定性图案/几何引擎**产生结果；
- 输出继续可编辑、可导出；
- 若运行时模型暂不可用，核心游戏和工坊无条件继续可用。

不得把“WorkBuddy 开发本应用时调用了 AI”写成“本应用在公开网页中已经真实接入 AI”。这两者要分别验收和披露。

# 5. 精确几何定义（必须按实现能力声明边界）

**这是项目科学与工程质量的核心验收项，先实现和测试它，再做漂亮动画。**

## 5.1 基础模型

初始纸张 `P` 是二维有界多边形区域；首版取中心位于原点的正方形

\[
P=[-a,a]\times[-a,a],\qquad a>0.
\]

一次或多次已实现的合法简单折叠把初始纸张划分成 `P_i`，各原始片区经过欧氏保距映射：

\[
f_i(x)=R_i x+t_i,\qquad R_i^TR_i=I,
\]

映射到最终平折纸包坐标中。这里 `R_i` 可包含镜像反射；每片记录原始域、变换和逆变换、最终覆盖范围、折叠历史、层次顺序/方向（仅当相关功能支持）。

> **关键区别**：二维几何决定所有最终形状；动画描述过程。动画不应构造第二套独立的结果状态。

## 5.2 初版允许的折叠集合

P0 必须明确限制为**经过验证的固定折叠预设**：

1. 不折叠；
2. 沿正方形竖直中线对折；
3. 沿水平中线对折；
4. 沿正交中线顺序各对折一次（折叠层次与方向固定并可显示）。

玩家可选择折叠预设并在其允许范围内调整切线。如果新增斜向或任意折线，必须提供它们的合法分区、每层变换与无穿透/可平折等相应验证；不做未经验证的任意折叠拖拽承诺。

**几何片区与物理纸张片层不是同一个概念。** 仅当 P0 物理语义充分明确时才声称相应真实折叠方法可打印复现；否则展示“二维几何模型示意”。

## 5.3 直线剪切语义

折叠纸包中定义直线 `L={x | n·x=c}` 和明确的移除半平面 `H^-={x | n·x<c}`（或另一侧，经用户选择和关卡指定）。令最终纸包各层在折叠平面的并集为 `F`，被移除的平面区域为 `D = F∩H^-`。将同一个切口施加于每一个实际覆盖它的纸层：

\[
S=\bigcup_i\bigl(P_i\setminus f_i^{-1}(D\cap f_i(P_i))\bigr).
\]

上式只刻画**所选择的半平面修剪操作**；需要确保显示的剪切与这种实际剪下和保留的语义一致。不要错误地将一条无面积的数学线段本身从纸张面积中相减后声称形成孔洞；真正的纸形计算必须处理被剪掉的一侧、连通区域和孔洞。

在允许的首版模式中用半平面裁剪/多边形布尔运算实现，并对跨多层覆盖的剪切逐层处理。不要对多个重合纸层仅剪切一次再把结果当作全部层的真实操作。

使用明确一致的坐标系、边界包含规则、容差与运算精度，并使数据类型、SVG 渲染坐标和屏幕像素映射分离。

## 5.4 黄金测试（不能跳过）

令 `P=[-a,a]^2`，经过竖直、水平正交对折后，折叠纸包在第一象限：

\[
(u,v)=(|x|,|y|),\quad 0\le u,v\le a.
\]

在纸包内剪除原点附近的三角形

\[
D=\{(u,v)\mid u\ge0,\ v\ge0,\ u+v<d\},\quad 0<d<a.
\]

最终展开孔洞必须为

\[
H=\{(x,y)\in P: |x|+|y|<d\},
\]

最终保留的纸区域为 `S=P\setminus H`。

数学验收指标：

- 孔洞是顶点为 `(±d,0),(0,±d)` 的菱形；
- 孔洞面积：`Area(H)=2d²`；
- 原纸面积：`4a²`；剩余面积：`4a²−2d²`；
- 对 `x`、`y` 轴的反射均保持图案不变；
- 用户改变 `d` 后，孔洞大小按真实几何结果改变，**不是切换预置图片**；
- 正确呈现 SVG 中部孔洞，支持导出后仍具有孔洞。

为防止退化，界面将 `d` 限定在有安全余量的合法范围内；准确处理 `d→0`、超出边界、斜线近共线等异常输入。

## 5.5 评分与正确性

对展开后纸区域 `A` 和关卡目标 `T`：

\[
\mathrm{IoU}=\frac{\operatorname{Area}(A\cap T)}{\operatorname{Area}(A\cup T)},\qquad
E=\frac{\operatorname{Area}(A\triangle T)}{\operatorname{Area}(P)}.
\]

按几何集而不是图像截图比较；允许小的浮点容差并以清晰文本区分“完全匹配（在容差内）”“接近”“未匹配”。需要生成差异区域可视化。对空区域、零面积并集等边界情况必须有定义。

**预设目标必须由合法折叠+合法切线的正向构造生成**，保留标准解、Seed 和可重复的验证用例。不能随意指定“龙形”“任意五角星”的照片就声称本首版引擎一定存在解。

## 5.6 几何库的职责边界

首选 `polygon-clipping` 支持 Polygon/MultiPolygon 的 union、intersection、difference、xor（https://github.com/mfogel/polygon-clipping）。它**不是完整的折纸引擎**；我们必须自己构建纸张分区、折叠反射、逆变换、层次信息、合法剪切和历史重建。

注意：多边形布尔算法、点集几何运算、渲染动画与实体制作检验是**四个不同的任务**。

# 6. 游戏关卡：原创、可验证、有解谜感

## 6.1 关卡设计

**目标：6 个独立且经验证的关卡。** 若因截止时间造成重大风险，至少优先保证 **3 个完整高质量关卡 + 一个可用工坊 + 可公开访问链接**，后续再补齐至 6。不得谎报关卡数量。推荐：

1. **角落初探**：无折叠，一条直线剪去一个角；学习切线、保留侧。
2. **镜像之门**：一条竖直中线对折，剪开后得到镜像图案。
3. **菱形奇迹**：两次正交对折，剪去纸包内角，展开中心菱形孔洞（数学黄金关）。
4. **大小之谜**：固定折叠，改变直线位置，调整孔洞尺度以匹配目标。
5. **角度之谜**：利用同一预设折叠，寻找一条不同斜率的合法切线复现目标。
6. **一刀终章**：隐藏构造参数，提供由正向生成器产生的有效目标与可逐步解锁的提示。

不得把六道只更换标题、实际操作相同的例子包装成完整游戏；至少从解谜目标、几何结果、交互提示上形成渐进变化。

## 6.2 每关数据结构

至少包含 `id`、标题、中英描述、难度、`foldPreset`、`allowedCutDomain`、`targetRegion`、`canonicalSolution`、`hintSteps`、验证器/误差阈值、知识点、关卡版本号。

设计三类提示：

- 观察提示：找到对称轴或缺失区域；
- 操作提示：应调整哪个参数；
- 解答提示：逐步展示已验证标准构造。

挑战可以失败，错误也应该有教育意义。出现错误不只是“失败”，而是显示“你的孔洞比目标大”“对称轴位置不一致”等依据几何差异可解释的反馈；不必把每种误差都交给 AI 猜测。

## 6.3 操作与体验

- 鼠标/触摸拖动切线两端或参数控制柄；
- 提供位置/角度/深度的辅助滑块和重置按钮；
- 可切换目标与结果叠层；
- 状态机：`ready -> folded -> cutting -> cut -> unfolding -> revealed -> scored`；
- 防止动画播放期间重复触发剪切和状态竞态；
- 支持暂停、重播、返回关卡、再次尝试；
- 本地记录尝试次数、最佳成绩、通过状态；
- 首次体验不能被登录、付费、模型 API 或广告阻断。

# 7. 剪纸工坊：真实创作与可导出作品

## 7.1 P0 必须实现

- 独立双视图：折叠纸包编辑 + 展开图案实时预览；
- 已实现折叠预设选择；
- 单切线交互、切线位置/角度/深度编辑；
- 默认中国红与其他 2–4 套优雅配色；
- 撤销/重做（修改真正的模型状态）；
- 重置；
- SVG 导出；
- PNG 高清导出（可选透明背景）；
- 本地保存、载入、删除；
- 数据版本与恢复错误处理。

## 7.2 P1 增强

- 多次剪切；
- 参数化的三角、菱形、圆弧/叶片孔洞；
- 至少 4 个原创美学预设：中国窗花、雪花、几何万花筒、节日祝福；
- 对称纹样的参数化生成：反射群、有限阶旋转对称；
- 编辑目标图案后，通过固定对称群的基本域逆映射生成候选切口；
- 自创图案分享卡片；
- 实体可折剪模板导出。

旋转对称的数字图案不能自动声称由当前折叠预设和单剪切可物理制作；使用展示标签说明图案生成机制。

## 7.3 SVG/PNG 必须是真数据

SVG 使用由几何引擎计算的 MultiPolygon / holes 转换得到的矢量路径，正确设置填充规则（如 `fill-rule="evenodd"` 或规范环绕方向）；不得将静态 PNG 嵌入 SVG 假装矢量。PNG 则从真实 SVG/Canvas 渲染导出。

导出结果需有可操作的文件名，例如 `foldyssey-diamond-20261030.svg`；确保离线打开可正确显示，不依赖远端图片。

## 7.4 真实手工模板的核验机制

实体折剪方案必须至少包含：纸张尺寸、折叠顺序、山谷折（如果已验证）、每一步纸包轮廓、切线和保留侧、最终预期轮廓、A4 等比例打印标尺。**必须确认该模板对应的真实可执行折叠与剪切，而不是只输出装饰图案。**

P0 可优先完成 SVG/PNG；可打印 PDF 或更复杂的实际制作说明列为 P1。若真实方案尚未验证，不允许挂上“可直接按步骤制作”的标签。

# 8. AI 创意设计师：产品内运行时模型的正确角色

## 8.1 AI 使用合规与清晰披露

WorkBuddy 开发时的编程模型与应用发布后运行时调用的模型**明确分开**。赛事是否强制内置 AI 需以官方原始规则核查为准；目前不得未经核验就写“参赛必须有运行时 AI”。

优先使用 WorkBuddy 官方支持的网站应用模型接入方式。在需求中明确“**接入大模型**”，避免要求最终用户自行申请密钥。API 密钥绝对不能进入客户端 JS bundle、Git 公开仓库或分享链接；服务端需安全存储并限流。

若平台无法提供合适的运行时 AI 能力：隐藏不可用入口/显示真实状态，保留全部数学游戏与工坊功能；不要用固定内容伪装真实大模型调用。投稿简介如实披露哪些 AI 功能真正上线。

## 8.2 AI 的价值定位

不是“生成一张窗花图片”，而是**将用户的创意转译为可以真实渲染、编辑、导出的参数化设计**。

输入示例：

- “设计一张喜庆的八瓣红色窗花，适合春节挂窗。”
- “我想做蓝白雪花，细致一些但尽量方便孩子剪。”
- “中秋主题，想要圆月、花瓣和简单的几何星星元素。”

模型负责：主题理解、设计风格、配色、已实现 motif 的选择与参数建议、命名、数学小知识、分享文案。

**几何引擎负责**：实际路径、对称映射、裁剪、合法性、最终面积/孔洞与实体可实现性验证。

## 8.3 数据契约与安全

构造受限 JSON schema（实际代码必须使用 Zod 等类型/Schema 校验）：

```json
{
  "theme": "spring_festival",
  "style": "traditional_papercut",
  "symmetry": { "type": "radial", "order": 8 },
  "palette": { "paper": "#B93645", "background": "#F8F3E9" },
  "motifs": [
    { "type": "petal", "size": 0.42, "rotation": 0 },
    { "type": "diamond", "size": 0.16, "rotation": 30 }
  ],
  "complexity": "medium",
  "title": "八瓣迎春"
}
```

以上**仅是参数化艺术工坊的示例**，并不自动对应物理折剪方案。严格定义 `theme/style/symmetry/motifs` 允许取值、motif 数量、order 合法范围、颜色格式、数值有限性、路径复杂度和最大尺寸。未知字段/未知图形类型应拒绝或明确降级，禁止任意 JS/HTML 执行或未清理的 SVG 注入。

对模型调用设置：输入长度、请求并发、超时、错误恢复、速率限制、预算；用户创作数据只在必要时发送，经界面提示，不传输整个私人作品库。

推荐的内部系统指令：

> 你是熟悉中国剪纸审美与计算几何的创意参数设计助手。只能在程序支持的枚举和数值范围内返回严格符合 Schema 的 JSON；不得编造任意图案的一刀可实现性、形式化证明、模型能力或学术来源。遇到尚未实现的复杂动物、文字或异形轮廓，应明确选择抽象几何表达或返回不支持。不要产生可执行代码、HTML、API Key、任意路径或绕过校验的指令。

前端错误状态必须有明显的“失败/重试/改用预设模板”，保证断网、API 限额和模型异常不会影响核心游戏。

# 9. 技术路线：二维几何 + 2.5D 动画，不做纸张物理引擎

## 9.1 首版技术栈（尽量轻量）

- React + TypeScript + Vite；
- Tailwind CSS（界面样式）；
- SVG 优先（纸张、剪切区域、折痕、矢量图案、导出）；
- `polygon-clipping`（多边形布尔运算）；
- `motion` / `motion/react`（交互反馈、折叠、切线、展开序列动画）；
- Vitest（数学/数据/组件测试）；
- Playwright（环境允许时进行端到端与多视口检查）；
- localStorage/IndexedDB（本地作品）；
- WorkBuddy 网站应用发布平台。

安装依赖示意：

```bash
npm install polygon-clipping motion
```

首版**不引入通用物理引擎**（如 Matter.js、Rapier）来模拟软纸的弹性、刚度、碰撞、重力、起皱。此类真实形变并非一刀剪切后平面结果的数学前提，开发风险高。

首版原则上**不引入 Three.js / React Three Fiber**。若二维/2.5D 无法完成基本视觉需求，可在**几何算法与 P0 关卡已通过测试**之后，评估仅为有限折叠动画加入轻量 Three.js；它不得替代几何引擎，更不得宣称自动解决物理可折性。

不要同时引入 Motion 和 GSAP 作为主动画系统。复杂时间轴若 Motion 当前能力不足，评估改用 GSAP，而非无规划叠加。

## 9.2 2.5D 动画方案

动画服务于真实纸片变换与折叠历史。建议：

1. **Fold**：分片沿真实折痕翻转/投影，显示背面、折痕高光、细微纸厚及阴影；对已实现的固定折叠采用明确端点状态；
2. **Cut**：剪刀或切线沿已计算的直线推进，使用 SVG clipping/mask 同步显示被切区域；碎纸可有装饰性飘落，但必须来自真实切下的区域；
3. **Unfold**：按折叠操作的逆序逐步展开，各片的最终位置与几何引擎一致；
4. **Reveal**：展开完成后让纸艺作品微微悬浮、投下柔和阴影、适度镜头放大，作为标志性的惊喜瞬间。

动画可以为复杂动作采用诚实的“二维步骤化示意”，但**不能只把一张最终图片放大，冒充物理折叠仿真**。必须允许暂停/重播；尊重 `prefers-reduced-motion`。如果 UI 当前处于“剪切中”不可重复触发导致重复删除几何区块。

```ts
  // include precise coordinate system, source patch set, layer ordering
};

type StraightCut = {
  nx: number;
  ny: number;
  offset: number;
  removedSide: 'negative' | 'positive';
};

type PuzzleLevel = {
  id: string;
  title: string;
  foldPreset: FoldPresetId;
  target: PaperRegion;
  canonicalSolution: StraightCut;
  hints: string[];
  tolerance: number;
};

type Artwork = {
  schemaVersion: number;
  id: string;
  title: string;
  foldPreset: FoldPresetId;
  cutOperations: StraightCut[];
  style: { paperColor: string; backgroundColor: string };
  manufacturability: 'verified' | 'digital-only' | 'unchecked';
};
```

实际类型禁止保留 `unknown` 替代核心几何结构；应采用清晰的 `Polygon/MultiPolygon` 类型、规范的坐标/环方向、输入验证器。折叠方向及顺序在复现时不可丢失。

保存作品需能从结构化状态重新计算，不能只缓存图片。对旧 schema 提供升级/错误提示。使用独立随机种子生成关卡时记录 seed；目标结果应附标准解并经自动验证。

# 12. 严格测试：数学、工程、视觉和发布四层验收

## 12.1 数学单元测试（P0，不可省略）

1. 不折叠且不剪切，结果为整个 `P`。
2. 单次反射及其逆变换恢复顶点，长度和面积不变。
3. 两次正交折叠后无剪切，展开恢复 `P`。
4. 黄金案例中心菱形：顶点、面积、对称性符合第 5.4 节。
5. 不同 `d` 可得到不同尺寸且面积正确的菱形；不存在静态图假象。
6. 合法直线穿过多层纸包时，每一层裁剪后的逆映射正确。
7. 切线不与纸包相交时得到明确反馈，不误删原纸。
8. 非法法向量、零长度控制柄、NaN/Infinity、退化多边形不崩溃。
9. 剪切后剩余区域为初始纸区域的子集（几何容差内）。
10. 剩余面积不大于初始面积，且不得出现负面积。
11. 相同输入、seed 和版本获得相同结果。
12. 环方向、多连通分量与孔洞能被正确导出 SVG。
13. 目标和实际完全相同时，IoU 近似 1、对称差近似 0。
14. 已知明显错误解不能被误判为通过。
15. 拖动交互所对应的坐标变换与算法坐标一致。

推荐属性测试：随机产生若干有效剪切参数，验证子集/面积/对称/逆变换等不变量；不要把随机测试代替黄金样例。

# 17. 不可接受的“伪完成”与风险约束

**严格禁止：**

- 用预制窗花图片假装用户剪切之后动态计算；

- 用图像像素相似度替代存在可靠几何区域时的严格几何评分；
- 把模型生成的 JSON/HTML/脚本未经校验直接执行；
- 在浏览器 bundle 暴露密钥；
- 没有部署就给一个虚构的正式 HTTPS 网址；
- 没有实际运行测试就写“0 error / all passed”；
- 活动原页面无法访问却自己编造报名表字段与官方规则；

# 18. 正式投稿演示：评委一眼看懂的 60 秒叙事

**演示目标**：不讲技术堆栈，也能让人明白是“数学可验证的数字剪纸游戏”。

- **0–5 秒**：宣纸背景上出现 Foldyssey，旁白/字幕“这一张纸，能剪出什么？”
- **5–12 秒**：两次正交对折，拖动一条斜切线。
- **12–21 秒**：按下 Snip，一刀切下，纸张逐层展开，中心镂空出现，画面定格。
- **21–33 秒**：切换谜题目标，移动切线，观察目标与实得差异，通关反馈。
- **33–47 秒**：进入工坊，调节参数/颜色，实时创作精美窗花；显示导出 SVG/PNG。
- **47–55 秒**：若已真实接入 AI，演示一句话生成可编辑参数化纹样；否则展示真正已完成的原创艺术预设或实体模板。
- **55–60 秒**：作品名、标语、真实公开体验链接/二维码。

必须确保这个脚本可以通过当前真实版本拍到，不用想象功能填补画面。准备竖屏/横屏截图至少各一组（数量由活动表单实际要求决定），图片体积严格按最终表单压缩。

推荐提交文案候选（根据真实功能修订）：

> **Foldyssey（一刀万象）**是一座可以玩的数字折剪纸实验室。折起一张纸、调整剪切线，只剪一刀，再亲手把层层纸张展开；图案来自可验证的计算几何，而不是预先准备的图片。你可以挑战原创谜题、创作自己的对称剪纸，并把作品导出为矢量图。让纸艺的惊喜，在一次展开中发生。

**不要在正式文案中提及没有真正上线的 AI 或打印模板功能。**
